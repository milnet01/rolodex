That is the most violent cap the three loops produced, and the diagnosis is about the run, not the document.** The pattern across all three loops is one thing: each fix pass added specific, checkable narration about `build.yml`'s internals to a standard that does not need it, and the next cold read found the narration wrong in a new way. Loop 3's fixes are therefore mostly DELETIONS. **All three lanes found the same Q2, and it is loop 2's own repair**: rule 2 says to apply a pin everywhere the dependency is installed, then narrowed the operative check to "every `pip install` line". Windows installs `cryptography` from MSYS2/pacman (`mingw-w64-ucrt-x86_64-python-cryptography`) and macOS installs PyInstaller by Homebrew, so a conformer pinning every pip line still ships a Windows binary built against the unpinned package — the exact failure rule 2 exists to prevent, on the one platform the enumeration missed. The check now says to search by dependency NAME rather than by command. **Two lanes found that loop 2's worked example inverted a security property.** It read that `build.yml` "pins the signing step's install so it cannot pull an unverified version while the key is in scope"; that step is named "Install signing dependency (no secret in scope)" and the workflow header says it installs "BEFORE the signing key is in scope, and only then signs". The protection is the two-job split, not the pin. Left standing, a conformer adding a release-job install would have put a pinned `pip install` inside the step carrying `SIGNING_KEY`, dissolving the boundary. The sentence was deleted rather than re-described. **The orchestrator found the sharpest Q1 itself, by reading a predicate instead of trusting an exit code.** Loop 2 added `pinact run --check` glossed as "every `uses:` SHA behind its latest release (exit 0 = all current)". `pinact run --help` says `--check` is "Alias for -fix=false"; `--update` is what compares against latest. The gloss was false, and loop 2's evidence for it — an observed exit 0 — under-determined the semantics exactly as the rule about reading predicates predicts. The block now runs `pinact run --update --check` and says it needs a GitHub token, because unauthenticated calls hit a 60/hour limit and report errors rather than staleness. **Two lanes found the `==` pin obligation had no check at all**; the block now greps workflow steps for exact pins, and that grep was run and returns the single real pin without matching `if: runner.os ==` noise. **One lane found "a bump pushed to a topic branch triggers no CI at all" false**: `pull_request: branches: [main]` carries no `types:`, so the default includes `synchronize` and a push to a branch with an open PR does run the suite. **One lane found the certifi coverage claim misleading**: the block prints the LOCAL certifi, while all three build jobs install it with `--upgrade`, so the shipped bundle is current by construction and the local number says nothing about a release. **Routing:** the cap is not a size signal — the document is 114 lines, in line with its siblings. Do not re-run this gate on this text. The residual risk is that a dependency standard narrates CI internals at all; if that narration goes stale again, the answer is to move it beside the workflows rather than to run a fourth loop. |
