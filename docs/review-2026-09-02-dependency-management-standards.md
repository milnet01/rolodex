# review-contract — docs/dependency-management-standards.md

Review record for `docs/dependency-management-standards.md`. The log is kept here rather than
in the document because this project keeps standards' review history in a dated `docs/` record
(`docs/review-2026-09-02-security-standards.md` set the precedent); the standard itself carries
no loop-log section.

Trigger: ROLO-0081. The forced-older-pin exception gained a precedence rule during ROLO-0062 —
it cannot take a dependency below a security floor — and that gate had not run.
Genre pinned `standard`, so Q4 was not asked. Cap is 3.

| 1 | 2026-09-02 | 3, cold — genre pinned `standard` | 3 | 0 | 3 | **Six verified, six fixed; one filed as ROLO-0084.** No Q2 — nothing in the document contradicted itself. **Two defects were found independently by all three lanes.** The first: the document claimed the test suite "runs in CI on every push", twice. `ci.yml` scopes both triggers to `main` (`push: branches: [main]`, `pull_request: branches: [main]`), so a push to a topic branch runs nothing — and a conformer bumping `cryptography` on a branch reads that sentence, believes the KDF and Fernet round-trip was checked automatically, and does only the manual steps. The second: nothing in the standard covered **commit-SHA pinning of GitHub Actions**, which this repo does on all six `uses:` lines. Read against "latest stable by default" and "an undocumented `==` pin is a standards violation", a conformer cannot tell whether the repo is already in breach: one files ledger rows with three empty columns, another repoints the actions at floating tags to comply — undoing the supply-chain protection. The standard now states that a SHA pin with its `# vX.Y.Z` comment is deliberate, is not a forced-older pin, owes no ledger row, and carries the obligation to move to each new release instead. **The sharpest single-lane finding was `certifi`.** The document called `cryptography` "the one security-critical PyPI dependency". `certifi` is a second: it is the CA bundle the frozen binaries' TLS trust depends on, installed by `build.yml` on all three platforms, asserted by `CI-local.sh`, and called "NOT optional" by the packaging scripts — while being deliberately absent from `requirements.txt` because it is build-time only. It matched none of the four dependency bullets, so the freshness sweep would never reach it and a stale CA bundle would ship inside a release binary. **Two more Q3s were about a pin nobody can honour.** `ci.yml` and `build.yml` install their dependencies with `pip install --upgrade` rather than from `requirements.txt`, so a forced-older pin recorded exactly as the standard instructs is silently ignored and CI stays green against a version nobody ships; the mandatory list now has a step requiring the pin everywhere the dependency is installed. And the `CHANGELOG` obligation named no triggering event — with the sole PyPI dependency unpinned, a 44→45 upgrade changes no file, so one conformer records every local upgrade and another records none. **One Q1 was a wrong-owner attribution**: this document said `security-standards.md` *sets* `cryptography >= 44.0.0`, while that document says `requirements.txt` sets the floor and the standard makes it override — so a conformer wanting to change the floor could not tell which artefact to edit. **4a step 3 caught a defect in one of this run's own fixes before it landed**: the `certifi` text as drafted said the packaging scripts *install* it, and they only name it in comments. Corrected before the write. **Collateral filed, not fixed:** `security-standards.md` carries the same "one security-critical dependency" claim; it reached its own review-contract cap on 2026-09-02, and correcting it changes what a conformer sweeps, so it re-arms that gate rather than riding along — ROLO-0084. |
